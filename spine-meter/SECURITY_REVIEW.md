# Security review (T25): spine-meter site

## Summary

The key handling is sound: the key lives only in a closure in `site/js/engine/token.js`, is trimmed and validated before storage, and is never written to storage, the URL, the console or the event log. The only request that carries it is the chat completions call in `site/js/engine/api.js`. No XSS sinks were found: model replies and data values reach the page only through `textContent`, `createTextNode` or fixed attributes. The CSP in `netlify.toml` matches what the pages load, with no inline code, no font, image or CDN references, and no mismatch. The main issue is cost control: the Gauntlet live mode sends paid calls with no cap or confirmation, and the batch confirmation understates the number of API attempts. Nothing is critical or high; one medium, four low and two info items remain.

## Checked and found clean

1. **Key handling.** The key is held in `storedText` inside `createTokenVault` (`token.js:32-57`). `set()` trims and validates it (`token.js:36-39`), and the dialog validates again (`token-dialog.js:57-58`). The only `localStorage` use is the theme key (`shell.js:94`, `104`). There are no `sessionStorage`, cookie, IndexedDB, Cache API, `history` or `location` writes. Forms are submit-prevented (`token-dialog.js:55-56`, `page-batch.js:154`). The input is cleared on close (`token-dialog.js:64`). There are no `console.*` calls in `site/`. All thrown messages are fixed text (`api.js:6-10`, `15`, `116`, `176`; `token.js:12`). A 401 or 403 gives a fixed message (`api.js:116`). Error response bodies are never read (`api.js:148`), so a server echo cannot leak into the UI. Runner events carry no key (`runner.js:62-64`, `92-99`, `123`), and saved records hold only fixed fields (`runner.js:80-89`).
2. **Requests.** `fetch` appears only in `api.js:139` (the configured endpoint) and in fixed-path loaders: `page-gauntlet.js:89`, `page-batch.js:185`, `page-live.js:47`, with paths at `page-gauntlet.js:14-19`, `page-batch.js:15-21`, `page-live.js:66-70`. The request body holds only model, messages, temperature and max_tokens (`api.js:180`). The Authorization header is set once, in `api.js:143`. Cross-origin fetch uses the default credentials mode, so no cookies are sent, as `API_DECISION.md` requires.
3. **XSS.** A grep of `site/js` and `site/*.html` finds no `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function` or string timers. Model text is written with `textContent` (`page-gauntlet.js:223`, `344`; `page-live.js:253`, `813`; `page-batch.js:658`) or `createTextNode` (`page-gauntlet.js:298`). `el()` (`ui.js:18-28`) sets text with `textContent`. Other attributes are code constants, or user-typed model names used as `value` and `title`. Links are constants (`shell.js:8-12`), and the download href is a blob URL (`page-batch.js:1056`). No `javascript:` URLs.
4. **CSP compliance.** There are no inline `<script>` or `<style>` blocks, no `style=` attributes and no `on*=` attributes (grep over `*.html`). The three module scripts are same-origin (`index.html:92`, `batch.html:246`, `live.html:134`). `setAttribute("style")` is not used. JavaScript style writes are allowed and are not findings: `page-batch.js:796-797` (progress width) and `charts/index.js:196-198` (SVG display, width, height).
5. **Downloads.** `downloadFile` (`page-batch.js:1054-1062`) creates a Blob and an object URL, attaches an anchor with a `download` name, clicks it, removes it, and revokes the URL after `REVOKE_DELAY_MS`. The CSV content (`page-batch.js:1065-1078`) and the JSON replies (`1081-1083`) are built from fixed-field records, so the key cannot be included.
6. **Data.** Across `site/data/*.json`: `Bearer` 0 matches, `TOKEN_FACTORY_TOKEN` 0, `sk-` prefix 0, and the words api key, secret, password and authorization 0. The provider name appears once (`config.json` base_url, expected). Long strings of 40 or more characters: `manifest.json` 8 lines, all hex hashes; `sample_run.json` 5 lines, 14 hex tokens and 2 mixed strings inside model reply fields, with no key-like prefix. The data is only read.
7. **Netlify headers.** The CSP (`netlify.toml:14-17`) matches the page loads. Scripts are same-origin modules. Each page loads three same-origin stylesheets. `css/fonts.css` has its font blocks commented out (8 open and 8 close comment markers), so no font is requested. No images or external links exist. Data loads and the chat call go to `api.tokenfactory.nebius.com`, which matches the `base_url` host. `_redirects` only maps paths. No mismatch was found.
8. **Denial and abuse.** No network call happens on page load: `page-gauntlet.js:104-120`, `page-batch.js:200-220` and `449-467`, and `page-live.js:722-752` and `908-988` only load data or plan from the cache. Start is the only trigger: `page-batch.js:170`, `page-live.js:958`. Pressing Enter in the custom model field only adds a model (`page-batch.js:164-169`). The batch flow is `handleStart` (`570-584`), then `showConfirmation` (`587-596`), then Continue (`599-603`), then `beginRun` (`615-648`). The cap is applied at `page-batch.js:621`, and every attempt is counted before it is sent (`api.js:126`). The live flow is `startLive` (`866-884`), with `askToContinue` (`755-775`) before `beginLiveRun` (`837-863`). The live cap is 1 to 400 (`page-live.js:35`, `869`). After Stop, no further attempt is sent (`api.js:103-106`). Retry backoff is capped at 60 seconds (`api.js:3`, `43`).
